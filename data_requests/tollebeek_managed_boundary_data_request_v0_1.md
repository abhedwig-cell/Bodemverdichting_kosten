# Tollebeek 1998 managed-boundary data request v0.1

Purpose: resolve `DR_SM_MANAGED_BOUNDARY` for event `EVT_TOL_1998_OCT` without backcasting the current IJsvogel/merged-OT.02 system.

Requested historical window: `1998-10-24T00:00:00Z` through `1998-10-30T00:00:00Z`, with highest priority on the 27-28 October crisis period.

Requested owner/archive evidence, preserving source-native timestamps/timezone, coordinates/location identity, vertical datum, units, QC and provenance:

1. surface-water levels at or representative of De Rietgors (OT02), De Fuut (OT03), De Kievit (OT04) and their tochten;
2. Urkervaart water level over the same period;
3. pump on/off, runtime, setpoint, capacity-state or realized-discharge records for the historical Rietgors/Fuut/Kievit installations;
4. stuw and inlaat operations that materially affected these peilgebieden;
5. emergency-pump location, start/stop time, nominal/realized capacity and receiving water during the crisis;
6. contemporary operator logs, calamity reports or event reconstructions sufficient to distinguish ordinary automatic control from emergency intervention.

Near-period official peil and capacity documentation may constrain a later reconstruction but is not a substitute for event telemetry. `NAP -6.20 m` is a nominal streefpeil, not an observed hydrograph. Current IJsvogel/current merged OT.02 operation is post-1998 and is excluded unless an explicit historical equivalence is independently justified.

## Qualified source-holder / archive route

Waterschap Zuiderzeeland is the primary source holder for the historical water-system records. Current owner material explicitly identifies the 1998 Tollebeek flooding as the event that preceded later system changes and confirms that the then-existing Rietgors/Fuut/Kievit pumping arrangement was materially different from the post-2010/IJsvogel system.

Use the following routing order:

1. **ordinary Zuiderzeeland information request** via the published Woo-contact/information route (`waterschap@zuiderzeeland.nl`, requesting the Woo-contactperson / historical water-information referral);
2. request referral to the relevant archive, peilbeheer, gemaal/asset, calamity or records-management custodian if the first-line contact does not hold the 1998 records;
3. use the formal Woo route only if relevant existing documents/records require a disclosure decision.

Zuiderzeeland's current Woo guidance explicitly advises first submitting an ordinary information request because many existing documents can be supplied without a formal Woo decision.

## Request identity

The request should state all of the following so archive selection is unambiguous:

- event: extreme rainfall/wateroverlast around Tollebeek, October 1998;
- primary time window: 24-30 October 1998, especially 27-28 October;
- historical system components: De Rietgors / OT02, De Fuut / OT03, De Kievit / OT04, related tochten and Urkervaart;
- requested evidence classes: level records, pump/runtime/operation logs, realized-discharge or capacity-state records, stuw/inlaat operation, emergency pumps, calamity/operator reports, contemporary event reconstructions;
- scientific purpose: reconstructing a bounded historical managed-water boundary for matched CURRENT/REFERENCE soil-state experiments;
- explicit exclusion: do not substitute present-day IJsvogel/current merged OT.02 data for 1998 records.

If source-native digital telemetry no longer exists, request the closest surviving primary documentation: handwritten/operator logbooks, archived printouts, calamity dossiers, maintenance/control records, board/project files, or later official reconstructions that explicitly cite the 1998 operational state.

## Acceptance after receipt

Receipt does not automatically admit an event boundary. Every record must retain source/date/version identity and be classified by directness:

- observed event telemetry/log = candidate `R0` support;
- near-period/retrospective constraint = candidate input to `R1` reconstruction;
- broad capacity/target-level context only = envelope/context, not hydrograph.

A numerical R1/R2 boundary requires a separate bounded workunit under the existing managed-boundary reconstruction protocol. No single nominal target level, installed capacity or later-system record may be silently converted into a 1998 hydrograph.
