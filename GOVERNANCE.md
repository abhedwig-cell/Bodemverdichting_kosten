# Governance

## Status-A-light principle

This repository uses a Status-A-like discipline without claiming that the project already satisfies a complete Status A dossier.

The governing chain is:

**theory → conceptual model → formal model → data model → implementation → evidence/qualification**.

A change should be traceable across the parts of this chain that it affects.

## Canonical versus artifact

Canonical project state consists of text schemas, documentation, code, evidence registers and tests under version control.

Excel workbooks, dashboards and application views are artifacts derived from or aligned with that canonical state. They are not automatically authoritative merely because they contain a value.

## Evidence inheritance

Evidence remains usable while its relevant dependencies and interpretation are unchanged. Historical benchmarks, scenarios and current model parameters must remain distinguishable.

## Change discipline

Use a separate branch or decision record when a change affects scientific meaning, the formal model, canonical schema, data ownership, or qualification logic. Small documentation corrections need not create a new scientific workstream.

## Minimum decision record

Material decisions should eventually capture: question, context, decision, alternatives considered, evidence, consequences, status and date.

## Current maturity

The repository is in bootstrap / pre-Status-A state. Missing sections should be marked explicitly rather than silently completed by assumption.
