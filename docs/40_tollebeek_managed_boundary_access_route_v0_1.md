## 1. Purpose

Qualify the owner/archive route for obtaining historical operational evidence needed to reconstruct the October-1998 Tollebeek managed-water boundary.

This workunit does not reconstruct or admit a numerical hydrograph, pump-dispatch series or event boundary.

## 2. Existing historical-system evidence

Canonical evidence and the qualified reconstruction protocol already establish that:

- October 1998 predates the current merged OT.02 / IJsvogel system;
- the historical system used separate underdrainage areas and installations including Rietgors, Fuut and Kievit;
- later IJsvogel/new-watercourse changes were responses to the 1998 water problem and must not be backcast silently;
- nominal target levels and near-period capacities constrain but do not identify realized event operation;
- emergency interventions materially matter and must be represented explicitly when reconstructing the event.

The current blocker is therefore:

`HISTORICAL_SYSTEM_TOPOLOGY_KNOWN — EVENT_OPERATION_RECORDS_UNRESOLVED`.

## 3. Owner evidence supporting archive search

Current Zuiderzeeland retrospective material identifies the 1998 Tollebeek wateroverlast as a major historical event and states that the old Rietgors/Fuut system was later replaced/expanded through the IJsvogel project. This confirms that the owner is an appropriate source holder for historical event and project records.

The published Woo/information guidance states that requesters should first use an ordinary information request when material is not already public, because many existing documents can be supplied without a formal Woo decision.

Thus the qualified access order is:

1. ordinary information request to Zuiderzeeland;
2. referral to records management / archive / peilbeheer / gemaal or calamity custodian;
3. formal Woo request only when disclosure of existing records requires it.

## 4. Target record classes

The request is tightly scoped to 24–30 October 1998, highest priority 27–28 October, and asks for source-native evidence for:

- Rietgors/OT02, Fuut/OT03 and Kievit/OT04 water levels;
- Urkervaart level;
- pump on/off, runtime, control/setpoint and realized-discharge/capacity-state records;
- stuw/inlaat operations;
- emergency pumps and temporary measures;
- operator/calAMity logs and official event reconstructions.

Where digital telemetry no longer survives, surviving primary or near-primary archival material is acceptable for classification: handwritten logs, printouts, calamity dossiers, asset/control records and contemporary board/project files.

## 5. Evidence-class boundary after receipt

Records must be classified before numerical use:

### R0 candidate support
Direct event-time observed water levels, pump logs, telemetry or contemporaneous operator records with sufficient source/time identity.

### R1 constraint support
Near-period capacities, archived operating rules, official event reconstructions or documentary evidence constraining when/how emergency intervention occurred.

### R2/context only
Nominal target levels, broad installed-capacity descriptions or later-system analogues without event-specific operational evidence.

No record is promoted merely because it is owner-issued.

## 6. Relationship to reconstruction protocol

The already qualified managed-boundary reconstruction ladder remains authoritative:

- R0 observed event boundary;
- R1 constrained historical reconstruction;
- R2 envelope-only scenario;
- R3 inadmissible default.

This access route supplies evidence to that ladder; it does not change the ladder or readiness status.

In particular:

- `NAP -6.20 m` remains target/context, not an event hydrograph;
- nominal pump capacity remains capacity context, not realized discharge;
- current IJsvogel operation remains post-1998 and excluded as a silent substitute;
- non-identifiability must remain explicit if archives do not resolve event operation.
